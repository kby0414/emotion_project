# EDA와 전처리

## 1. 입력 데이터

원본은 다양한 해상도와 방향을 가진 JPG/JPEG 이미지와 JSON 라벨이다. Training과 Validation에 같은 폴더 구조를 사용하며, 원본과 전처리 결과는 섞지 않고 별도 보관한다.

| 구분 | 원본 라벨 레코드 | 보유 JPG | 전처리 성공 | 손상 제외 |
|---|---:|---:|---:|---:|
| Training | 417,167 | 223,578 | 223,570 | 8 |
| Validation | 52,126 | 52,126 | 52,118 | 8 |
| 합계 | 469,293 | 275,704 | 275,688 | 16 |

### 1.1 Training 데이터 축소 결정

감정별 Training 원천 데이터는 part 0~3의 4개 파트로 구성돼 있었다. 전처리 시간과 세 모델 학습 시간을 줄이기 위해 데이터 양을 약 절반으로 제한했다.

- 검토안 1: 4개 파트를 모두 내려받은 뒤 각 파트에서 70~80%를 무작위 삭제
- 검토안 2: 4개 파트 중 2개 파트만 내려받아 사용

검토안 1은 전체 다운로드 후 삭제 대상 선정과 검증이 추가되어 작업량이 커지고, 무작위 표본을 다시 만들기 위한 목록이나 seed 관리도 필요하다. 프로젝트 기간을 고려해 범위가 명확하고 추가 작업이 적은 검토안 2를 선택했다.

라벨 JSON은 전체 파트 범위가 남아 있어 선택하지 않은 파트에 해당하는 Training 라벨 193,589건은 대응 원천 JPG가 없다. 따라서 이 수치는 전처리 실패가 아니라 **계획한 파트 단위 데이터 축소로 인한 원천 미보유**로 설명한다.

## 2. EDA에서 확인한 내용

- 7개 클래스 비율은 각각 약 14.13~14.35%로 균형적이다.
- Training 라벨 417,167건 중 193,589건은 파트 단위 데이터 축소로 대응하는 원천 JPG를 사용하지 않았다.
- 보유 원본 275,704장 중 JPEG 스트림이 손상된 16장은 제외했다.
- 한 사람이 여러 장의 유사한 이미지를 제공하는 구조이며, Training과 Validation에 공통으로 등장하는 파일명 선두 식별자가 528개다. 이 식별자가 동일 인물 또는 촬영 세션을 뜻한다면 검증 성능이 낙관적일 가능성이 있다.
- 원본 해상도 범위가 넓고 EXIF 방향에 의존하는 이미지가 많았다.

더 상세한 분포와 근거는 `results/preprocessing_eda_report.md`에 있다.

## 3. 전처리 선택과 이유

| 처리 | 선택 이유 | 한계 |
|---|---|---|
| 224×224 | 세 사전학습 모델의 대표 입력 규격이며 244보다 호환성이 좋음 | 미세 표정 일부 축소 가능 |
| EXIF 방향 보정 | 옆이나 거꾸로 저장된 픽셀을 정상 방향으로 통일 | EXIF가 잘못 기록된 파일은 별도 확인 필요 |
| 1채널 흑백 | 형태와 명암에 집중하고 저장 공간 감소 | 피부색·홍조 등 색상 정보 손실 |
| 종횡비 유지+검정 패딩 | 얼굴이 강제로 늘어나거나 눌리는 변형 방지 | 검정 여백이 생김 |
| PNG | 재저장 손실 없이 같은 입력 유지 | 경우에 따라 JPEG보다 큼 |
| 손상 JPEG 제외 | 깨진 픽셀을 학습 노이즈로 사용하지 않음 | 표본 16장 감소 |

## 4. 처리 순서

```text
JPG/JPEG 재귀 탐색
  → 중복 출력 경로 검사
  → JPEG 디코딩과 손상 검사
  → EXIF 방향을 픽셀에 실제 적용
  → 흑백 변환
  → 종횡비 유지 축소
  → 중앙 검정 패딩으로 224×224 통일
  → PNG 임시 저장 후 원자적 교체
  → JSON filename을 .png로 변경
  → 얼굴 박스에 배율과 패딩 좌표 적용
  → 오류·개수·시간을 summary에 기록
```

추가 하위 폴더가 있어도 `rglob` 재귀 탐색을 사용하므로 `EMOIMG_기쁨_TRAIN_01` 같은 폴더 안의 이미지까지 찾는다.

## 5. 실행 방법

```powershell
.\.venv\Scripts\python.exe .\src\preprocess_data.py
```

주요 기본값은 `size=224`, `channels=1`, 검정 패딩, Training과 Validation 모두 처리다. 정상적으로 이미 만들어진 PNG는 다시 저장하지 않으므로 재부팅이나 강제 종료 후 같은 명령을 실행해 이어갈 수 있다.

완료되면 다음 파일이 생성된다.

```text
dataset/processed/preprocessing_summary.json
```

이 파일이 없으면 전체 과정이 끝나기 전에 중단됐을 가능성이 있다.

## 6. 손상 파일 분석

처리하지 못한 16장은 경로나 한글 파일명 문제가 아니라 JPEG 픽셀 스트림 자체의 손상 또는 잘림이었다.

| 오류 | 수량 |
|---|---:|
| `broken data stream` | 15 |
| `truncated` | 1 |
| 합계 | 16 |

전체 원본의 약 0.0058%로 매우 적고, 강제 복원한 깨진 픽셀은 학습 노이즈가 될 수 있어 제외했다. 실패 경로와 원인은 summary JSON에 보존했다.

## 8. 학습 단계와 연결

전처리 PNG는 1채널이지만 ImageNet 사전학습 모델은 3채널 입력을 기대한다. 학습 로더에서 흑백 이미지를 동일 값의 RGB 3채널로 복제하고 ImageNet 평균과 표준편차로 정규화한다. 따라서 색상 정보가 복구되는 것은 아니며 모델 입력 형식만 맞추는 과정이다.
