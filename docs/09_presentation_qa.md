# 발표 질문과 답변

## 1. 왜 224×224를 선택했나요?

“비교한 ResNet18, MobileNetV2, EfficientNet-B0가 ImageNet 사전학습에서 일반적으로 사용하는 입력 규격이 224×224이기 때문입니다. 244보다 torchvision 모델 호환성과 기존 가중치 활용이 좋고, 27만 장 규모에서 학습 시간과 GPU 메모리도 줄일 수 있어 224를 선택했습니다.”

## 2. 왜 이미지를 강제로 224×224로 늘이지 않고 패딩했나요?

“원본 비율을 무시하고 정사각형으로 늘리면 얼굴이 눌리거나 길어져 표정 특징이 왜곡될 수 있습니다. 긴 변을 224에 맞춰 축소하고 남는 공간을 검정색으로 패딩해 얼굴 비율을 유지했습니다.”

## 3. 왜 흑백으로 변환했나요?

“표정 인식에서 중요한 눈·입·눈썹의 형태와 명암에 집중하고 저장 용량과 입력 복잡도를 줄이기 위해 흑백을 선택했습니다. 다만 피부색이나 홍조 같은 색상 정보가 사라지는 한계가 있어 향후 RGB 데이터와 같은 조건으로 ablation test가 필요합니다.”

## 4. 흑백인데 왜 모델에서는 RGB 3채널로 바꾸나요?

“색상을 되살리는 과정이 아니라 ImageNet 사전학습 모델의 입력 형식을 맞추기 위한 것입니다. 같은 흑백 값을 R·G·B 세 채널에 복제한 뒤 ImageNet 정규화를 적용합니다.”

## 5. 왜 JPG를 PNG로 바꿨나요?

“전처리 결과를 다시 저장할 때 JPEG 손실이 추가되지 않도록 무손실 PNG를 사용했습니다. 입력을 매번 동일하게 유지하고 손상 여부를 관리하기 좋다는 장점이 있습니다.”

## 6. 왜 Training 라벨보다 원천 이미지가 적나요?

“감정별 Training 원천 데이터는 4개 파트로 나뉘어 있었고, 제한된 시간 안에 전처리와 세 모델 학습을 마치기 위해 그중 2개 파트만 사용했습니다. 전체 파트를 받은 뒤 70~80%를 무작위 삭제하는 방법도 검토했지만 다운로드와 선별 작업이 늘어 파트 단위 선택을 사용했습니다. 라벨은 전체 범위가 남아 있어 선택하지 않은 파트의 193,589건은 대응 JPG가 없습니다. 전처리 실패가 아니라 계획한 데이터 축소 결과입니다.”

## 7. 처리 실패 이미지가 있었던 이유는 무엇인가요?

“최종 전수 검사에서 275,704장 중 16장이 실패했습니다. 한글 경로나 코드 문제가 아니라 JPEG 내부 데이터 스트림 손상과 잘림이 원인이었습니다. 비율이 약 0.0058%로 매우 작고 강제 복원 시 깨진 픽셀이 학습 노이즈가 될 수 있어 제외하고 경로와 원인을 summary JSON에 기록했습니다.”

## 8. 거꾸로 된 이미지는 어떻게 처리했나요?

“일부 원본은 실제 픽셀이 회전되어 있고 EXIF 태그를 지원하는 뷰어에서만 정상으로 보였습니다. 전처리 단계에서 EXIF 방향을 픽셀에 직접 적용했고 총 83,308장을 보정했습니다.”

## 9. TensorFlow가 아니라 PyTorch를 선택한 이유는 무엇인가요?

“이번 프로젝트는 PyTorch와 torchvision으로 통일했습니다. ResNet18, MobileNetV2, EfficientNet-B0를 같은 API로 구성할 수 있고 학습 반복문, Macro-F1 계산, 중단 재개, 체크포인트 저장을 직접 관리하기 편했기 때문입니다. TensorFlow의 성능이 부족해서가 아니라 프로젝트 재현성과 관리 편의성을 위한 선택입니다.”

## 10. GPU 사용을 어떻게 검증했나요?

“먼저 `nvidia-smi`로 NVIDIA GPU와 드라이버를 확인했습니다. 이후 `torch.version.cuda`와 `torch.cuda.is_available()`을 확인하고 GPU에서 실제 행렬 곱셈까지 실행했습니다. 단순히 CUDA라는 문자열이 보이는 것뿐 아니라 PyTorch CUDA 커널이 정상 작동하는지 검증했습니다.”

## 11. 왜 이 세 모델을 골랐나요?

“ResNet18은 안정적인 기준선, MobileNetV2는 경량·실시간 모델, EfficientNet-B0는 정확도와 효율의 균형을 대표합니다. 서로 다른 장점을 가진 세 구조를 같은 데이터와 학습 조건에서 비교해 웹캠 프로그램의 정확도와 속도 선택지를 확보했습니다.”

## 12. 왜 Accuracy만 사용하지 않았나요?

“Accuracy는 전체 정답률이지만 특정 클래스에 성능이 치우쳐도 그 문제를 충분히 보여 주지 못합니다. Macro-F1은 7개 감정의 F1을 같은 비중으로 평균하므로 각 감정을 고르게 분류하는지 평가할 수 있습니다. 세 모델 비교에서는 두 지표와 클래스별 F1을 함께 확인했습니다.”

## 13. 왜 한 모델만 최종 모델로 선택하지 않았나요?

“세 모델의 Validation 성능 차이가 크지 않고 장점이 서로 다르기 때문입니다. EfficientNet-B0는 현재 정확도가 가장 높고, MobileNetV2는 가장 가벼우며, ResNet18은 안정적인 기준선입니다. 프로그램에서 세 모델을 모두 제공해 사용자가 선택하거나 같은 입력의 결과와 속도를 비교하도록 구성했습니다.”

## 14. 프로그램에서 세 모델을 어떻게 실행하나요?

“일반 모드에서는 선택한 모델 하나만 실행해 실시간 속도를 확보합니다. 비교 모드에서는 같은 얼굴 ROI를 세 모델에 입력하고 각 모델의 감정명, 신뢰도, FPS와 지연 시간을 함께 표시합니다. 세 모델 동시 추론은 느려질 수 있어 비교 모드는 필요할 때 활성화합니다.”

## 15. 50 epoch를 설정했는데 왜 18~21 epoch에서 끝났나요?

“검증 Macro-F1이 3회 연속 개선되지 않으면 멈추는 early stopping을 적용했기 때문입니다. 50은 최대 학습 횟수이며 실제 최적점 이후 불필요한 계산과 과적합을 줄였습니다. 최고 가중치는 종료 시점이 아니라 best epoch의 `best.pt`로 저장했습니다.”

## 16. 데이터셋의 한계는 무엇인가요?

“Training은 시간 제약으로 감정별 4개 파트 중 2개만 사용했으므로 전체 데이터 결과로 해석할 수 없습니다. 또한 한 사람당 유사한 이미지가 여러 장 있고, Training과 Validation에 동일 인물 또는 촬영 세션일 가능성이 있는 식별자도 겹칩니다. 같은 사람의 특징을 학습한 효과로 정확도가 높게 측정됐을 수 있으므로, 완전히 새로운 사람에 대한 성능은 인물·촬영 세션 기준 group split이나 외부 데이터로 추가 검증해야 합니다.”

## 17. 웹캠 프로그램에 전달할 파일은 무엇인가요?

“ResNet18, MobileNetV2, EfficientNet-B0 실험 폴더의 각 `best.pt`입니다. 파일에는 최고 가중치뿐 아니라 모델 이름, 클래스 순서, 입력 크기, 정규화 값도 포함됩니다. `last.pt`는 학습 재개용이므로 프로그램 추론에는 사용하지 않습니다.”

## 18. 발표 마무리 문장

“원본 이미지의 손상과 방향 문제를 근거와 함께 관리하고 27만 5천여 장을 동일한 224×224 흑백 입력으로 만들었습니다. 같은 데이터에서 학습한 ResNet18, MobileNetV2, EfficientNet-B0를 웹캠 프로그램에 모두 탑재하고, 모델 선택 모드와 비교 모드에서 예측 결과와 실시간 속도를 확인할 예정입니다.”
