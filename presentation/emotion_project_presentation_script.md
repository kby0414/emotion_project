다음 단계에서는 웹캠으로 프레임을 입력받고 얼굴을 검출한 뒤, 학습 때와 동일하게 전처리하여 세 모델의 감정 예측과 확률을 화면에 표시할 예정입니다.

## 슬라이드 5. 데이터 범위와 품질 점검 — 약 90초

EDA에서 확인한 핵심 문제는 네 가지입니다.

첫째, Training 원천 데이터는 각 감정마다 part 0부터 3까지 4개 파트로 나뉘어 있었습니다. 데이터 양이 매우 많고 프로젝트 시간은 제한되어 있어, 전처리와 세 모델 학습 시간을 줄이기 위해 약 절반만 사용하기로 했습니다.

처음에는 4개 파트를 모두 받은 뒤 각 파트에서 70에서 80퍼센트를 무작위로 지우는 방법도 생각했습니다. 하지만 전체 다운로드 후 다시 선별하고 검증하면 작업이 크게 늘고, 무작위 표본을 재현하기 위한 관리도 필요합니다. 그래서 더 단순하고 범위가 명확한 방법으로, 4개 파트 중 2개 파트만 내려받아 사용했습니다.

라벨 JSON은 전체 파트 범위가 남아 있었기 때문에 선택하지 않은 파트의 라벨 19만 3,589건에는 대응 JPG가 없습니다. 이 숫자는 전처리 코드의 실패나 예상하지 못한 누락이 아니라, 시간 제약에 따라 의도적으로 데이터 범위를 줄인 결과입니다.

둘째, 실제로 보유한 JPG 가운데 16장은 JPEG 데이터 스트림이 손상되거나 잘려 있어 정상적으로 디코딩할 수 없었습니다. 이는 한글 경로나 파일명 문제는 아니었습니다.

셋째, 이 데이터에는 같은 사람이 촬영한 유사한 표정 이미지가 여러 장 있습니다. Training과 Validation에서 파일명 앞부분의 공통 식별자도 528개 발견됐습니다. 이 식별자가 같은 사람이나 같은 촬영 세션을 의미한다면, 모델이 감정 특징뿐 아니라 이미 학습한 사람의 얼굴 특징을 이용했을 수 있습니다. 따라서 정확도가 높더라도 완전히 새로운 사람에게 같은 성능이 나온다고 단정할 수 없습니다.

넷째, 많은 이미지가 EXIF 방향 정보에 의존하고 있었습니다. 따라서 일반 뷰어에서는 정상으로 보여도 실제 픽셀은 회전된 상태일 수 있어, 전처리 과정에서 방향 정보를 픽셀에 직접 적용했습니다.

## 슬라이드 6. 전처리 설계 — 약 65초

전처리의 목표는 표정의 형태를 최대한 보존하면서 세 모델이 받을 입력 규격을 통일하는 것이었습니다.

먼저 이미지 크기는 244가 아니라 224 곱하기 224로 선택했습니다. 이번에 사용한 세 모델이 ImageNet 사전학습에서 일반적으로 사용하는 대표 입력 크기이고, torchvision의 사전학습 가중치와 호환하기 좋기 때문입니다. 27만 장이 넘는 데이터를 학습할 때 연산량과 GPU 메모리를 관리하기에도 적절했습니다.

이미지를 정사각형으로 강제로 늘리면 얼굴이 길어지거나 눌릴 수 있습니다. 그래서 원본 종횡비를 유지한 채 긴 변을 224에 맞춰 축소하고, 남는 부분만 검정색으로 채웠습니다.

또한 눈, 입, 눈썹의 형태와 명암에 집중하고 저장 공간을 줄이기 위해 1채널 흑백으로 변환했습니다. 다만 피부색이나 홍조처럼 색으로 나타나는 감정 단서가 사라질 수 있으므로, 향후 RGB 입력과의 비교 실험이 필요합니다.

저장 형식은 전처리 결과에 JPEG 재압축 손실이 추가되지 않도록 PNG를 선택했습니다. 학습 시에는 흑백 값을 RGB 세 채널에 똑같이 복제해 사전학습 모델의 입력 형식을 맞춥니다. 이 과정이 색상 정보를 되살리는 것은 아닙니다.

## 슬라이드 7. 이미지 변환 전후 — 약 30초

왼쪽은 고해상도 RGB 원본이고, 오른쪽은 전처리한 224 곱하기 224 흑백 PNG입니다.

오른쪽 이미지가 정사각형이지만 얼굴 자체의 비율은 바뀌지 않았습니다. 원본의 가로세로 비율을 유지해 축소하고 남는 영역만 검정색으로 패딩했기 때문입니다. 또한 EXIF 방향을 먼저 적용했기 때문에, 저장 상태와 관계없이 모델에는 정상 방향의 픽셀이 입력됩니다.

## 슬라이드 8. 전처리 결과 — 약 55초

최종적으로 27만 5,688장의 이미지 전처리에 성공했고, 손상된 JPEG 16장은 제외했습니다. 제외 비율은 전체 보유 원본의 약 0.0058퍼센트로 매우 작습니다. 깨진 픽셀을 강제로 복원하면 오히려 학습 노이즈가 될 수 있어 제외하는 편이 합리적이라고 판단했습니다.

방향을 보정한 이미지는 8만 3,308장이었고, 이미지 크기 변경에 맞춰 JSON 라벨의 얼굴 박스 82만 7,064개도 같은 비율과 패딩 위치로 변환했습니다.

전체 처리 시간은 1시간 35분 35초였으며, 이미지 저장 용량은 약 513.40기가바이트에서 12.85기가바이트로 약 97.50퍼센트 감소했습니다.

컴퓨터가 재부팅되거나 작업이 중단되는 상황도 고려했습니다. 이미 완성된 PNG는 건너뛰고, 파일을 임시 이름으로 완성한 다음 최종 이름으로 교체하도록 했습니다. 처리 결과와 오류 원인은 `preprocessing_summary.json`에 기록했습니다.

## 슬라이드 9. PyTorch GPU 환경 — 약 55초

학습 환경은 Python 3.12.10 가상환경과 CUDA 12.6용 PyTorch로 구성했고, 실험에는 NVIDIA GeForce RTX 4060을 사용했습니다.

GPU 확인은 설치 화면만 보는 것으로 끝내지 않았습니다. 먼저 `nvidia-smi`로 GPU와 드라이버 인식을 확인했습니다. 여기서 표시되는 CUDA 버전은 드라이버가 지원하는 상한에 가깝기 때문에, 실제 PyTorch가 사용하는 CUDA 런타임은 `torch.version.cuda`로 따로 확인했습니다. 이후 `torch.cuda.is_available()`을 확인하고 GPU에서 실제 행렬 곱셈까지 실행해 CUDA 커널이 정상 동작하는 것을 검증했습니다.

TensorFlow 대신 PyTorch를 선택한 이유는 성능이 부족해서가 아닙니다. torchvision에서 세 모델을 같은 API로 불러올 수 있고, 학습 반복문과 Macro-F1 계산, AMP, 체크포인트, 중단 재개를 한 코드에서 직접 관리하기 편했기 때문입니다.

## 슬라이드 10. 비교 모델 — 약 65초

비교 모델은 서로 다른 목적을 대표하도록 선정했습니다.

먼저 ResNet18은 잔차 연결을 사용하는 모델입니다. 여러 층을 통과한 결과에 이전 입력을 더해 기울기가 깊은 층까지 잘 전달되도록 돕습니다. 구조가 널리 검증됐고 학습이 안정적이어서 이번 프로젝트의 기준선으로 사용했습니다. 세 모델 중 파라미터는 약 1,118만 개로 가장 많습니다.

MobileNetV2는 depthwise separable convolution과 inverted residual, linear bottleneck을 사용해 연산량과 파라미터를 줄입니다. 파라미터가 약 223만 개로 세 모델 중 가장 작기 때문에, 웹캠이나 자원이 제한된 환경에서 빠른 추론을 기대할 수 있습니다. 다만 실제 실시간 속도는 웹캠 프로그램에서 FPS와 지연 시간을 측정해 확인해야 합니다.

EfficientNet-B0는 네트워크의 깊이, 너비, 입력 해상도를 균형 있게 확장하는 compound scaling을 바탕으로 합니다. MBConv와 SE 구조를 활용하며, 약 402만 개의 파라미터로 이번 Validation에서는 가장 높은 성능을 보였습니다.

이렇게 안정적인 기준선, 경량성, 정확도와 효율의 균형을 대표하는 세 구조를 같은 데이터와 학습 조건에서 비교했습니다.

## 슬라이드 11. 학습과 평가 설계 — 약 60초

세 모델에는 같은 Training과 Validation 데이터를 사용했습니다. 학습 데이터에는 좌우 반전과 작은 회전, 이동, 확대 정도의 약한 증강만 적용했습니다. 표정의 의미를 바꿀 수 있는 강한 변형은 피했습니다.

공통 설정은 최대 50 epoch, batch size 32, 초기 learning rate 0.0003, seed 42입니다. optimizer는 AdamW를 사용했고, weight decay 0.0001과 label smoothing 0.1을 적용해 과도한 확신과 과적합을 줄이려고 했습니다. 학습률은 Cosine scheduler로 점차 낮췄으며, GPU에서는 AMP를 사용해 연산 속도와 메모리 사용을 개선했습니다.

주 평가 지표는 Accuracy가 아니라 Validation Macro-F1로 정했습니다. Accuracy는 전체 정답률이지만, Macro-F1은 일곱 감정의 F1을 같은 비중으로 평균하기 때문에 각 감정을 고르게 분류하는지 확인하기 좋습니다.

Macro-F1이 세 번 연속 개선되지 않으면 조기 종료했고, 가장 높았던 시점의 가중치를 `best.pt`로 저장했습니다. 따라서 50 epoch는 반드시 모두 실행하는 횟수가 아니라 최대 학습 횟수입니다.

## 슬라이드 12. 세 모델의 검증 성능 — 약 55초

세 모델의 Validation 결과를 비교하면 EfficientNet-B0의 Accuracy는 0.7400, Macro-F1은 0.7357로 가장 높았습니다.

MobileNetV2는 Accuracy 0.7309, Macro-F1 0.7296이었고, ResNet18은 Accuracy 0.7275, Macro-F1 0.7253이었습니다. Macro-F1 기준으로 EfficientNet-B0와 MobileNetV2의 차이는 약 0.0062, ResNet18과의 차이는 약 0.0104로 크지 않습니다.

따라서 EfficientNet-B0가 현재 Validation에서 가장 좋은 모델이라는 사실은 비교 결과로 제시하되, 이를 단일 최종 모델 선정으로 해석하지 않았습니다. MobileNetV2는 훨씬 작은 모델이고 ResNet18은 안정적인 기준선이라는 별도의 가치가 있어, 세 모델을 모두 프로그램에 탑재할 계획입니다.

## 슬라이드 13. 감정별 F1 — 약 50초

전체 평균만 보면 모델이 어떤 감정을 어려워하는지 알기 어렵기 때문에 클래스별 F1도 확인했습니다.

기쁨은 세 모델 모두 약 0.95, 중립은 약 0.83으로 비교적 잘 구분했습니다. 당황과 분노는 약 0.76에서 0.77, 슬픔은 약 0.71에서 0.72 수준이었습니다.

반면 불안은 약 0.56에서 0.57, 상처는 약 0.50에서 0.54로 세 모델 모두 낮았습니다. 특정 모델 하나만의 문제가 아니라 공통적으로 나타난 약점입니다. 불안과 상처의 표정 특징이 다른 부정 감정과 비슷하거나 라벨의 감정 경계가 모호했을 가능성이 있습니다.

따라서 다음 개선에서는 단순히 더 큰 모델을 추가하기보다, 불안과 상처의 오분류 이미지를 직접 확인하고 라벨 기준과 데이터 품질을 분석하는 작업이 중요합니다.

## 슬라이드 14. 학습 결과 분석 예시 — 약 45초

이 슬라이드는 세 모델 가운데 EfficientNet-B0의 결과를 분석 예시로 보여 줍니다. 최종 모델을 하나로 결정했다는 의미는 아닙니다.

학습 곡선을 보면 학습 정확도는 계속 올라가지만 검증 성능은 약 0.74 부근에서 정체됩니다. 최고 성능은 15 epoch에서 나왔고, 이후 세 번 연속 Macro-F1이 개선되지 않아 18 epoch에서 조기 종료됐습니다. 이는 학습 실패가 아니라 최적점 이후의 불필요한 연산과 과적합을 줄인 결과입니다.

혼동행렬에서도 상처와 불안 같은 감정이 다른 부정 감정과 섞이는 경향을 확인할 수 있습니다. 이 결과는 앞의 클래스별 F1에서 확인한 공통 약점과도 연결됩니다.

## 슬라이드 15. 세 모델 체크포인트와 팀 전달 파일 — 약 40초

학습 결과는 각 모델의 `best.pt`로 저장했습니다. 웹캠 프로그램 담당자에게는 ResNet18, MobileNetV2, EfficientNet-B0의 `best.pt` 세 개를 모두 전달합니다.

체크포인트에는 가중치만 있는 것이 아니라 모델 이름, 일곱 개 클래스의 순서, 입력 크기, 정규화 값과 최고 검증 지표도 함께 들어 있습니다. 프로그램에서는 이 정보를 읽어 학습 때와 같은 전처리와 클래스 순서를 유지해야 합니다.

`last.pt`는 optimizer와 scheduler 상태까지 포함한 학습 재개용 파일입니다. 실제 추론 프로그램에서는 마지막 epoch 파일이 아니라 각 모델의 최고 Macro-F1 시점인 `best.pt`를 사용합니다.

## 슬라이드 16. 현재 결과의 한계 — 약 65초

현재 결과에는 네 가지 한계가 있습니다.

가장 중요한 부분은 한 사람의 유사 이미지가 많고, Training과 Validation에 동일 인물이나 촬영 세션일 가능성이 있는 식별자가 겹친다는 점입니다. 같은 사람의 이미지가 두 분할에 모두 들어갔다면 모델이 감정 특징과 함께 그 사람의 얼굴 특징을 기억해 정확도가 높게 측정됐을 수 있습니다. 따라서 현재 수치는 제공된 Validation 기준이며, 완전히 새로운 사람에게도 같은 성능을 보장한다고 말할 수는 없습니다. 향후에는 같은 인물의 이미지를 반드시 한쪽 분할에만 배치하는 group split 검증이 필요합니다.

또한 Training은 시간 제약으로 감정별 4개 파트 중 2개만 사용했습니다. Training 라벨 19만 3,589건의 대응 JPG가 없는 이유도 이 계획된 범위 축소이므로, 전체 원천 데이터가 아니라 실제 사용한 두 파트 기준의 결과라고 명확히 보고해야 합니다.

현재는 흑백 입력만 실험했기 때문에 RGB 입력과의 직접 비교도 필요합니다. 마지막으로 학습 환경 기록상 MobileNetV2와 나머지 두 모델의 PyTorch 버전이 달랐습니다. 더욱 엄밀한 비교를 위해서는 동일한 패키지 버전이 기록된 환경에서 세 모델을 다시 재현하는 것이 좋습니다.

## 슬라이드 17. 웹캠 프로그램 구조 — 약 55초

웹캠 프로그램에서는 먼저 프레임에서 얼굴을 검출하고 얼굴 영역인 ROI를 자릅니다. 이 얼굴 이미지를 학습 때와 똑같이 흑백으로 바꾸고, 비율을 유지한 채 224 곱하기 224로 패딩합니다.

그다음 일반 모드에서는 사용자가 선택한 모델 하나만 실행해 실시간 속도를 확보합니다. 비교 모드에서는 동일한 얼굴 ROI를 세 모델에 입력해, 각 모델이 예측한 감정과 신뢰도, FPS, 평균 지연 시간을 함께 표시합니다.

이때 체크포인트에 저장된 클래스 순서와 ImageNet 정규화 값을 그대로 사용해야 학습 환경과 추론 환경이 일치합니다. 세 모델을 매 프레임 동시에 실행하면 속도가 떨어질 수 있으므로, 비교 모드는 일정 프레임 간격으로 실행하거나 사용자가 필요할 때만 활성화하는 방식을 고려하고 있습니다.

## 슬라이드 18. 세 모델 웹캠 비교 결과 추가 페이지 — 약 30초

마지막 슬라이드는 웹캠 프로그램 구현 후 결과를 추가하기 위한 페이지입니다. 현재 회색 영역에는 실제 모델 선택 화면과 감정명, 신뢰도, 모델 이름이 보이는 웹캠 화면을 넣을 예정입니다.

오른쪽에는 같은 컴퓨터와 같은 입력 조건에서 측정한 ResNet18, MobileNetV2, EfficientNet-B0의 FPS와 평균 지연 시간을 기록하겠습니다. 이 결과를 통해 정확도 순위만 보는 것이 아니라, 세 모델이 실제 프로그램에서 보이는 예측 차이와 속도 차이까지 비교할 수 있습니다.

정리하면, 이번 프로젝트에서는 데이터의 손상과 방향 문제를 근거와 함께 관리해 27만 5,688장을 동일한 입력으로 만들었고, 서로 다른 장점을 가진 세 모델의 학습과 저장까지 완료했습니다. 앞으로 세 모델을 모두 웹캠 프로그램에 연결해 선택 모드와 비교 모드로 검증하겠습니다. 이상으로 발표를 마치겠습니다. 감사합니다.

## 발표 중 반드시 구분할 표현

- `193,589건`은 전처리 실패나 예상하지 못한 누락이 아니다. 시간 제약으로 Training 4개 파트 중 2개만 사용하면서 선택하지 않은 파트에 남은 라벨 수다.
- 실제 전처리에서 제외한 파일은 손상 JPEG `16장`이다.
- `0.7400 Accuracy`와 `0.7357 Macro-F1`은 현재 제공 Validation에서의 EfficientNet-B0 결과다. 새로운 사용자에게 같은 성능을 보장하는 수치가 아니다.
- EfficientNet-B0는 현재 검증 수치가 가장 높지만, 단일 최종 모델로 선정한 것이 아니다. 프로그램에는 세 모델을 모두 넣는다.
- MobileNetV2의 작은 파라미터 수는 경량성의 근거지만, 실제 웹캠 속도는 FPS와 지연 시간을 측정한 뒤 결론낸다.
- 50 epoch는 최대값이다. 세 모델이 18~21 epoch에서 종료된 이유는 Macro-F1 기준 조기 종료가 정상적으로 작동했기 때문이다.
- 한 사람의 유사 이미지가 Training과 Validation 양쪽에 포함되면 정확도가 높게 측정될 수 있다. 현재 결과와 새로운 사람에 대한 일반화 성능을 구분해 말한다.
